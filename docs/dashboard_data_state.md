# JALDRISHTI AI — Data State, System Mode & Map State Protocol

## 1. Objective
To prevent operational ambiguity and misleading claims during emergency flood monitoring, JALDRISHTI AI strictly disaggregates **System Mode**, **Data State**, and **Map State**.

---

## 2. Three-Tier State Taxonomy

```
┌───────────────────────────┬──────────────────────────────────┬───────────────────────────┐
│        SYSTEM MODE        │            DATA STATE            │         MAP STATE         │
├───────────────────────────┼──────────────────────────────────┼───────────────────────────┤
│ • LIVE                    │ • LIVE                           │ • LIVE_MAP                │
│ • REPLAY                  │ • DEGRADED                       │ • OFFLINE_MAP             │
│ • SIMULATION              │ • STALE                          │                           │
│                           │ • OFFLINE                        │                           │
│                           │ • NOT_CONFIGURED                 │                           │
│                           │ • REAL_HISTORICAL                │                           │
│                           │ • REAL_HISTORICAL_HINDCAST       │                           │
│                           │ • SYNTHETIC                      │                           │
└───────────────────────────┴──────────────────────────────────┴───────────────────────────┘
```

### A. System Mode (Operational Pipeline Context)
1. `LIVE`: Autonomous background scheduler executing real-time polling and model inferences against live upstream APIs.
2. `REPLAY`: Time-travel historical playback of verified flood events (`EVT-MAHANADI-2024-08`, `EVT-MAHANADI-2022-08`, `EVT-MAHANADI-2020-08`).
3. `SIMULATION`: Interactive operator sandbox for what-if scenario testing and parameter stress testing.

### B. Data State (Sensor & Model Ingestion Authenticity)
1. `LIVE`: Verified live telemetry or satellite feed ingested within the required product latency.
2. `DEGRADED`: Telemetry received with missing sensor channels or spatial gaps.
3. `STALE`: Telemetry timestamp older than $2\times$ the expected ingestion cadence.
4. `OFFLINE` / `UNAVAILABLE`: Data feed unreachable or actively rejected by quality control.
5. `NOT_CONFIGURED`: Adapter present in codebase but lacking valid API credentials.
6. `REAL_HISTORICAL`: Genuine archival records from IMD/CWC/Sentinel-1.
7. `REAL_HISTORICAL_HINDCAST`: Strictly leak-free retrospective model evaluation executed with cutoff timestamps.
8. `SYNTHETIC`: Generated test patterns for pipeline verification.

### C. Map State (Cartographic Tile Rendering Engine)
1. `LIVE_MAP`: OpenStreetMap online raster tile service operational and responding.
2. `OFFLINE_MAP`: Fallback vector canvas active, rendering all scientific layers without external tile dependencies.

## 3. Strict Sensor & Model State Rules

### Radar Status Protocol
- When the Paradip Doppler Weather Radar (`DOPPLER_RADAR_PARADIP`) is not receiving real binary sweeps, the UI **MUST NEVER** display `LIVE RADAR` or a green operational pulse.
- Required Label: `RADAR UNAVAILABLE (FUSED SATELLITE/AWS)` or `RADAR NOT CONFIGURED`.

### ConvLSTM Model Labeling Protocol
- The model label `ConvLSTM` / `RAIN_L3_CONVLSTM` is restricted to inferences generated by the genuine PyTorch spatiotemporal sequence architecture.
- If an analytical decay model is active, it must be labeled `Analytical Storm Decay`.

### Benchmark Metrics Labeling Protocol
- Benchmark charts must explicitly denote the dataset partition:
  - `[REAL HISTORICAL HINDCAST]`
  - `[HELD-OUT TEST]`
  - `[TRAIN / DEVELOPMENT]`
- Metrics must never be replaced with arbitrary placeholders or zeros when missing; unavailable metrics must show `N/A` or `NOT AVAILABLE`.
